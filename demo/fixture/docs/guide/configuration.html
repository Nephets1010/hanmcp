Configuration

Orbital reads configuration from CLI flags, then from orbital.toml, then from environment variables. Flags win. Nothing is required: every option has a default that is safe on a 64 MB device.

Options

OptionDefaultDescription
retention30dHow long samples are kept before the partition dropper removes them.
memory-budget8mbUpper bound on resident memory for the write cache and the index.
fsyncintervalOne of always, interval, never. Durability versus write throughput.
flush-interval2sHow often the write cache is flushed into an immutable segment.

The memory budget

Memory is not a soft limit. Orbital reserves the budget up front and refuses to start if the requested budget exceeds the container limit, because silent swapping on a gateway is worse than a failed boot. The index costs roughly 12 bytes per distinct series, and the write cache takes the remainder.

For 200,000 series the index alone needs about 2.3 MB, which leaves 5.7 MB of a default budget for the write cache. If your series count is larger than that, raise memory-budget rather than lowering flush-interval: flushing more often increases write amplification on flash storage.

Durability trade-offs

With fsync = always every accepted write is on disk before the call returns, which costs roughly 40% of peak throughput on eMMC. With interval you can lose up to flush-interval worth of samples on power loss, which is the right default for telemetry that is re-sent by the collector anyway.
