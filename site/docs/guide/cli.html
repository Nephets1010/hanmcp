Command line reference

The interface is three subcommands and a short list of flags. Everything has a default that is safe to run against somebody else's site, so the common case needs no configuration at all.

Commands

hanmcp <url> [options]        crawl a documentation site and build the server
hanmcp serve [dir]            run the generated server over stdio
hanmcp help | version

Flags

  • --out <dir> — output directory. Defaults to mcp-docs.
  • --max-pages <n> — hard ceiling on pages fetched. Defaults to 50, which covers most product documentation sites.
  • --max-depth <n> — link depth from the entry URL. Defaults to 2.
  • --name <name> — server name registered with the MCP client. Defaults to the site title.
  • --delay <ms> — pause between requests. Defaults to 120 milliseconds.
  • --no-robots — skip the robots.txt check. Off by default, and you should have a reason.
  • --force — overwrite the output directory even if hanmcp did not create it.
  • --quiet — print only the final summary. Use this in CI.

The scope rule

This is the one behaviour that surprises people, so it is worth stating precisely. The trailing slash decides the crawl scope. Given /docs/ the entire subtree is in scope, so every page underneath it is eligible. Given /docs/v2/start.html with no trailing slash, only the containing directory is in scope. The rule exists so that pointing at a single page to try the tool out does not silently drag in an entire website.

The safety rule

hanmcp refuses two output directories outright: a filesystem root, and your current working directory. It also refuses to delete a directory it did not create unless you pass --force. Ownership is recorded by a marker file written the moment the directory is created, not at the end of the build, so an interrupted or failed build leaves a directory that a later run can still safely reuse. Deleting somebody's folder because they mistyped --out is not an acceptable failure mode.

Crawler politeness

Requests identify themselves honestly as hanmcp. robots.txt is fetched and honoured before the first page request, a Crawl-delay directive overrides the default delay, and non-HTML responses are dropped rather than indexed as empty pages. Cross-origin links are never followed.
